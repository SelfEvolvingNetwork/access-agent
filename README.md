# ایجنت دسترسی (access-agent)

> مخاطب: مالک/نصاب پل + عامل مرکزی (A1، کلاه بازیاب پل I5) · عامل پروژهٔ عضو (A2) این مخزن را نمی‌خواند — مسیرت: ROLES §۲ در مخزن پرستو

> **نقشهٔ جامع مستندات خانوادهٔ پرستو (۴ مخزن):** [`docs/INDEX.fa.md` در مخزن `parastoo`](https://github.com/SelfEvolvingNetwork/parastoo/blob/main/docs/INDEX.fa.md) — تنها درگاه ورود به مستندات (ترتیب خواندن شروع سرد + «موضوع → سند مرجع»).

پل دسترسی **مستقل و همیشه‌روشن** برای عامل هوش مصنوعی به سرور — مستقل از پرستو، مستقل از داکر، مستقل از هر چیز دیگری که ممکن است کرش کند.

## چرا این پروژه وجود دارد؟ (تصمیم معماری ۲۰۲۶-۱۱-۰۵ مالک)

تا پیش از این، تنها مسیر دسترسی عامل هوشمند به سرور، خودِ پرستو بود (`/api/dev/*` روی پنل). اگر پرستو در نصب یا به‌روزرسانی شکست می‌خورد، عامل هیچ کاری نمی‌توانست بکند و **حلقهٔ تست و توسعه می‌شکست** — دقیقاً همان‌طور که در استقرار v0.3.9 (502 پایدار) اتفاق افتاد.

ایجنت دسترسی این حلقهٔ شکسته را می‌بندد:

```
مالک ──یک فرمان SSH──▶ ایجنت دسترسی (systemd، مستقل) ──▶ آدرس + توکن موقت
                                                              │
عامل هوش مصنوعی ◀───────── HTTPS + پین گواهی ────────────────┘
   │
   ├── دستور اجرا روی هاست (معادل SSH)
   ├── نصب/بازراه‌اندازی/تعمیر پرستو (حتی وقتی کاملاً پایین است)
   ├── تست و راستی‌آزمایی هر چیز روی سرور
   └── گرفتن توکن گیت‌هاب برای پوش (custodian: پات مالک روی سرور ذخیره است)
```

**اصل:** کاربر پس از نصب ایجنت دسترسی، هیچ کار دیگری روی سرور ندارد؛ همهٔ درخواست‌هایش را از طریق عامل هوش مصنوعی دنبال می‌کند — حتی نصب پرستو.

## نصب یک‌فرمانی (روی سرور، با SSH)

```bash
curl -fsSL https://raw.githubusercontent.com/SelfEvolvingNetwork/access-agent/main/bootstrap.sh | sudo bash
```

با ذخیرهٔ توکن گیت‌هاب مالک در همان لحظهٔ نصب (اختیاری ولی توصیه‌شده):

```bash
curl -fsSL https://raw.githubusercontent.com/SelfEvolvingNetwork/access-agent/main/bootstrap.sh | sudo ACCESS_AGENT_GITHUB_TOKEN=ghp_xxx bash
```

در ایران اگر گیت‌هاب مستقیم باز نشد:

```bash
curl -fsSL https://gh-proxy.com/https://raw.githubusercontent.com/SelfEvolvingNetwork/access-agent/main/bootstrap.sh | sudo bash
```

**وابستگی‌ها فقط:** `python3` + `openssl` + `systemd` + `curl`. نه داکر، نه pip، نه هیچ بستهٔ دیگر — کل سرویس با کتابخانهٔ استاندارد پایتون اجرا می‌شود.

## بعد از نصب چه می‌شود؟

نصب‌کننده یک کارت گزارش چاپ می‌کند و در `/etc/access-agent/install-report.txt` (chmod 600) ذخیره می‌کند:

- `ACCESS_URL` — مثل `https://93.151.142.128:25437` (پورت تصادفی آزاد)
- `CERT_SHA256` — اثر انگشت گواهی خودامضای ۱۰ساله؛ عامل هوش مصنوعی این را پین می‌کند
- `AGENT_TOKEN` — توکن عامل؛ **این را به عامل هوش مصنوعی بدهید**
- `ADMIN_TOKEN` — توکن ادمین؛ **فقط پیش خودتان بمانید**، هرگز برای عامل نفرستید

مالک این سه مقدار (به‌جز ADMIN_TOKEN) را در چت به عامل هوش مصنوعی می‌دهد و از این پس عامل ابتکار عمل را در دست می‌گیرد: اتصال، تست، نصب/تعمیر پرستو، همه‌چیز.

**متن تحویل آماده (v0.1.3):** لازم نیست سه مقدار را دستی بازنویسی کنی — نصب‌کننده در پایان، بلوک آمادهٔ کپی‌پیست چاپ می‌کند و هر وقت خواستی:

```bash
sudo access-agent handoff
```

همین بلوک را می‌دهد: سه مقدار + لینک قرارداد + مأموریت یک‌خطی. آن را عیناً در چت عامل هوش مصنوعی بچسبان.

**دعوت‌نامهٔ کوتاه (v0.7 — توصیه‌شده):** توکن عامل بلندمدت دیگر لازم نیست از چت عبور کند؛ عاملِ بی‌خبر که توکنِ زنده در پیام اول می‌بیند، بدگمان می‌شود و مأموریت را رد می‌کند. به‌جایش:

```bash
sudo access-agent invite        # یا با TTL دلخواه: sudo access-agent invite 30
```

بلوک کوتاهی می‌دهد با فقط سه مقدار غیرمخفی: آدرس سرور، هش گواهی، و یک کد آشناسازیِ یک‌بارمصرف. نخستین تراکنش عامل `GET /api/agent/onboarding` است (فقط‌خواندنی، بدون توکن) و دستورالعمل کامل را خود سرور به او می‌دهد؛ بعد کد را با توکن موقتِ ۸ ساعتهٔ مخصوص همان مکالمه عوض می‌کند و در پایان مکالمه با `POST /api/agent/session/end` پاکش می‌کند. جزئیات: `docs/AGENT_PROTOCOL.fa.md` §۱.۵. برای هر مکالمهٔ تازه، دعوت‌نامهٔ تازه بسازید.

## مدل امنیتی

| لایه | تصمیم |
|---|---|
| دو قلمرو توکن | `admin` (ادمین سرور) و `agent` (عامل هوش مصنوعی)؛ ادمین superset است |
| ذخیرهٔ توکن | فقط هش SHA-256 در `tokens.json` (chmod 600)؛ مقایسهٔ constant-time |
| انتقال | فقط HTTPS با گواهی خودامضا؛ عامل اثر انگشت گواهی را پین می‌کند |
| توکن گیت‌هاب | **حالت GitHub App (v0.2 — پیشنهادشده):** پل با کلید خصوصی اپ، توکن نصب واقعی ≤۱ساعته می‌سازد که خودش می‌میرد و فقط به مخزن‌های نصب‌شده می‌رسد؛ پات مالک هرگز سرو نمی‌شود. **حالت فالبک (بدون اپ):** پات مالک فقط در `/etc/access-agent/github.env` (chmod 600، خارج از هر git)؛ عامل با هدف ثبت‌شده آن را می‌گیرد (افشای نشست‌محور + رکورد grant). راهنما: `docs/GITHUB_APP_GUIDE.fa.md` |
| audit | هر فراخوانی در `audit/audit.jsonl` (append-only) — خط قرمز: عامل حق ویرایش ندارد |
| سقف‌های exec | cmd ≤ ۱۶۳۸۴ کاراکتر، timeout ≤ ۶۰۰ث، خروجی ≤ ۲۰۰هزار کاراکتر/جریان، هم‌زمانی ≤ ۲ (بیشتر → 429)؛ **v0.5.1 — یک بازیگر تغییردهنده در هر لحظه:** حین عملیات lifecycle پرستو، execِ متضاد با نصب/آپدیت/حذف 409 `lifecycle_busy` می‌گیرد و شروع lifecycle حین execِ متضاد 409 `exec_busy` (پایان ساختاری رخداد race تایمر، LESSONS پرستو) |
| stdin | همیشه `/dev/null` (درس `curl \| bash` پرستو) |

چرخش و قطع توکن عامل هر وقت خواستید، یک فرمان است (بالا) — و `bootstrap.sh` را دوباره اجرا کنید، **کد ارتقا می‌یابد و همهٔ توکن‌ها/گواهی/پات/audit دست‌نخورده می‌مانند**.

## مرجع API (خلاصه؛ شرح کامل: `docs/AGENT_PROTOCOL.fa.md`)

| مسیر | دسترسی | کارکرد |
|---|---|---|
| `GET /healthz` | عمومی | سلامت سبک |
| `GET /` | عمومی | اطلاعات سرویس |
| `GET /api/status` | agent \| admin | وضعیت هاست (آپ‌تایم، دیسک، رم، داکر، مسیر نصب پرستو، وضعیت توکن‌ها) |
| `POST /api/exec` | agent \| admin | اجرای دستور روی هاست (معادل SSH) |
| `POST /api/github/token` | agent \| admin | توکن گیت‌هاب با هدف ثبت‌شده — v0.2: توکن نصب واقعی ≤۱ساعته (GitHub App)؛ فالبک: افشای نشست‌محور پات |
| `GET /api/admin/audit` | admin | دم audit |
| `GET /api/admin/audit/stream` | admin | **v0.3 — جریان زندهٔ SSE audit** (مانیتور موبایل)؛ `?cursor=` ادامه از آفست بایت، `?backfill=N` تاریخچهٔ اولیه |
| `GET /api/admin/sessions` | admin | فهرست grantهای توکن گیت‌هاب |
| `GET /api/admin/agent-token` | admin | **v0.3** — متادیتای توکن عامل (برچسب/زمان) — هرگز خود توکن را نمی‌دهد |
| `GET /api/admin/handoff` | admin | **v0.3** — همان بلوک تحویل آمادهٔ کپی برای عامل، سرو شده به ادمین (پرستو موبایل) |
| `POST /api/admin/agent-realm/pause` | admin | **v0.3 — کلید توقف**: توقف/ادامهٔ کل قلمرو عامل با دلیل؛ در `state.json` ماندگار است؛ ادمین همیشه آزاد |
| `POST /api/admin/rotate-agent-token` | admin | توکن عامل جدید (قدیمی می‌میرد؛ v0.3: برچسب اختیاری در متادیتا) |
| `POST /api/admin/revoke-agent-token` | admin | قطع قلمرو عامل |
| `POST /api/admin/set-github-token` | admin | ذخیره/تعویض پات مالک |
| `POST /api/admin/bridge/uninstall` | admin | **v0.5.7 — پاک کردن خود پل** (آخرین فرمان نقطهٔ صفر؛ `{"confirm": "uninstall"}`): کد، راز‌ها، توکن‌ها، گواهی و audit پل برای همیشه حذف می‌شوند؛ همهٔ دسترسی راه‌دوری می‌میرد — عمدی. اجرا با واحد گذرای systemd تا از توقف سرویس جان سالم به‌در بَرد. قرارداد کامل: `docs/AGENT_PROTOCOL.fa.md` §۵.۷ |
| `GET /api/admin/app/core-config` | admin | **v0.5.8 — هستهٔ هات اپ موبایل**: پاکت داده نسخه‌دار (نقشهٔ endpointها + متن‌های مجاز + فلگ‌ها) که اپ 0.4.12+ بدون نصب مجدد APK واکشی و اعمال می‌کند. فقط داده (هرگز کد)، پوشش sha256، اورراید سروری در `ACCESS_AGENT_HOME/app-core/core.json` با فالبک امن به پیش‌فرض. قرارداد کامل: `docs/AGENT_PROTOCOL.fa.md` §۵.۸ |

## پرستو موبایل (v0.3 — ادمین در جیب)

اپ اندروید رسمی مدیریت و مانیتورینگ: مخزن [`SelfEvolvingNetwork/parastoo-mobile`](https://github.com/SelfEvolvingNetwork/parastoo-mobile).

- ادمین سرور را با URL + اثرانگشت گواهی + توکن ادمین اضافه می‌کند؛ ورودهای بعدی با قفل گوشی (بیومتریک/PIN).
- «بلوک تحویل» آماده را با یک لمس می‌سازد و کپی می‌کند (`POST /api/admin/rotate-agent-token` + `GET /api/admin/handoff`) — عامل جدید فقط کپی می‌خواهد.
- **مانیتور زنده بدون بار روی عامل:** همه‌چیز سمت پل ثبت و از طریق SSE (`GET /api/admin/audit/stream`) به موبایل می‌آید؛ عامل هیچ گزارشی تولید نمی‌کند.
- **کلید توقف:** `POST /api/admin/agent-realm/pause` — قلمرو عامل فوراً ۴۰۳ می‌گیرد، ادمین و healthz دست‌نخورده، پس از ریستارت هم برقرار.
- پیش‌نیاز: access-agent ≥ **v0.3.0** روی سرور (ارتقا: اجرای دوبارهٔ `bootstrap.sh` — توکن‌ها/گواهی/audit حفظ می‌شوند).

## فرمان‌های مالک روی سرور (CLI کمکی)

```bash
sudo access-agent status                 # وضعیت سرویس + آدرس + سلامت
sudo access-agent url                    # فقط ACCESS_URL
sudo access-agent show-agent-token       # توکن عامل (برای دادن به عامل)
sudo access-agent rotate-agent-token     # توکن جدید؛ قدیمی می‌میرد
sudo access-agent revoke-agent-token     # قطع دسترسی عامل
sudo access-agent show-admin-token       # توکن ادمین (فقط خودتان) — v0.1.1
sudo access-agent rotate-admin-token     # توکن ادمین جدید؛ قدیمی می‌میرد — v0.1.1
sudo access-agent set-github-token ghp_xxx   # تعویض پات (اعتبارسنجی best-effort)
sudo access-agent handoff                 # متن آمادهٔ تحویل به عامل هوش مصنوعی — v0.1.3
sudo access-agent audit 30               # دم لاگ audit
```

## حذف کامل

```bash
curl -fsSL https://raw.githubusercontent.com/SelfEvolvingNetwork/access-agent/main/uninstall.sh | sudo bash
```

پیش‌فرض `secrets/audit` را نگه می‌دارد؛ با `--purge` همه‌چیز پاک می‌شود. پرستو هرگز لمس نمی‌شود.

## نقشهٔ راه

- **v0.3 (این نسخه):** پرستو موبایل — جریان زندهٔ SSE audit، کلید توقف قلمرو عامل، متادیتای توکن عامل، endpoint بلوک تحویل، رکورد exec غنی‌شده برای مانیتور
- **v0.1.3:** متن تحویل (handoff) — بلوک آمادهٔ کپی‌پیست برای عامل هوش مصنوعی، در خروجی نصب و فرمان `access-agent handoff`
- **v0.2:** توکن موقت واقعی گیت‌هاب با GitHub App (توکن نصبی ۱ساعتهٔ فقط-مخزن) — مالک یک‌بار App می‌سازد؛ مسیر افشا به‌عنوان فال‌بک می‌ماند
- **v0.4:** کانال آپدیت پایدار (تگ) + آپدیتر خودکار access-agent جدا از پوش‌های main
- هر زمان: تعویض گواهی خودامضا با ACME اگر دامنه به این سرویس وصل شد

## خطوط قرمز (غیرقابل مذاکره)

1. توکن/رمز فقط در `/etc/access-agent/`؛ هرگز در کد، کامیت، لاگ یا گزارش.
2. `audit.jsonl` فقط‌افزایشی است — عامل حق ویرایش/پاک‌کردن آن را ندارد.
3. عامل ADMIN_TOKEN را هرگز دریافت یا درخواست نمی‌کند.
4. بدون تأیید مالک: `uninstall`، حذف audit، تعویض ADMIN_TOKEN، تغییر مسیرهای `-ETC` پیش‌فرض.
5. پوش به گیت‌هاب فقط با چک‌های سبز محلی (`python tests/smoke_test.py` + `bash -n`).
